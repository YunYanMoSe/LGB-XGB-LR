## 一、链路总览与新增产物（一键对照）

把"物品向量 + 协同过滤"收敛为一条可服务链路：**多路召回（候选池）→ 特征工程 → LR/LightGBM 精排 → Flask 在线 API**，并补齐指导书要求的落盘产物：

| 指导书要求 | 本仓库产物 | 说明 |
|---|---|---|
| 用户购买序列 | `data/processed/user_sequences.csv` | 397,884 行；用户视角按时间排序（customer_id 已存 int64，无 `17850.0` 尾巴） |
| Item2Vec 规范模型 | `models/item2vec.model` | 阶段五 Skip-gram 全量模型的规范命名副本（词表 3,177） |
| 向量索引 | `models/vector_index/` | `keys.npy + vectors_unit.npy + meta.json`，行归一化，供 `/similar` |
| 多路召回集 | `data/processed/recall_set.csv` | 142,150 行 = 2,843 用户 × 50 候选（含路由贡献 / 归一化融合分） |
| LR 精排模型 | `models/lr_model.pkl` | `StandardScaler + LogisticRegression` Pipeline |
| LightGBM（可选对比） | `models/lgb_model.pkl` | 同特征同候选 |
| 排序元信息 / 在线排序函数 | `models/rank_meta.json`；`src/recommender.py::score_rank` | 特征顺序、系数、AUC、案例、重叠；在线打分入口 |
| 演示 ID | `models/demo_ids.json` | 演示用户 `12597 / 13899`，演示商品 `85123A / 22423` |
| Flask 服务 | `web/app.py` | `/health` `/` `/similar` `/recommend` `/baseline`，任一加 `&format=json` 返回 JSON |

### 统一的离线口径（防泄漏铁律，全链路一致）

- 每用户**最后一笔订单 = 测试篮**，更早历史 = 训练（query 时刻）。
- 热度 / 商品向量 / 用户画像 / ItemCF 全部只用**训练期**数据计算。
- 商品向量用训练期订单现重训一份 Skip-gram（训练期语料 13,112 个订单、词表 3,046），
  不泄漏测试篮 —— 与 `scripts/08` 同做法，缓存于 `outputs/chain/vectors_train_skip.npz`。
- 网页/演示 API 用全量语料向量索引与全量历史 ctx（商品语义/已购历史属静态知识，无评估标签，不涉防泄漏）。

> **口径一致性说明（重要）**：本链路把 ItemCF 基线按"用训练历史预测下一单"重测，
> 故数字（hit@10≈0.28）与阶段四/五报告素材中的 ItemCF 0.377/0.383 **不同**——
> 那是"**以测试篮商品为种子**做同篮相似补全"的变体（相当于已知当前单内容），
> 而阶段六所有方法（含热门/ItemCF 基线）都在"**只用更早历史预测下一单**"这一任务上重测，
> 表与表之间、行与行之间才是同一口径可比。

## 二、多路召回与候选池（对应阶段四）

三路召回按配额 `热门 10 : 相似扩展 20 : 用户向量 20` 融合去重，不足 50 用热门回填；
每路由内部名次先归一化到 0~1（避免"热门路分数=负名次、被压到队尾"的量纲假象）再排序取 Top-50。
`recall_set.csv` 每行一个候选：`user_id, item, recall_rank, routes(用|连接), score(归一化融合分), n_routes`。

阶段四指标（2,843 个测试用户；结果存档 `outputs/chain/recall_phase4.txt|.json`）：

| 指标 | 数值 | 怎么读 |
|---|---|---|
| 命中用户占比（Top50 至少 1 个命中下一单） | **40.2%** | 接近一半用户能在召回池里找到"下一单会买"的商品，池子"装得进答案" |
| 平均 recall@50 | 0.0445 | 测试篮平均约 20 种商品（中位 14）、且历史已购被排除后，50 个候选中平均每用户命中约 0.9 个（命中用户内平均约 2.2 个）；批发补货篮里"可命中空间"本身有限 |
| 召回集商品覆盖率 | **77.9%**（2,809 / 3,608 种） | 所有用户召回集去重后覆盖训练期商品库的近 8 成——冷门品也有机会被不同用户捞到 |
| 热门占比（Top100 热门行/总行） | 27.2% | 候选池并不只是"热门榜"，个性化路由占大头 |
| 多路命中占比（≥2 路都召回该候选） | 5.5% | 三路信号互补性强、重复少：热门管"大众常买"，相似扩展管"同篮成套"，用户向量管"口味迁移" |
| 各路由至少贡献 1 条候选的用户占比 | 热门 100% / 相似 99.8% / 用户向量 100.0% | 配额在几乎所有用户上都落实 |

结论：**融合召回的价值在"候选池"的覆盖率与多路供给**，而不是它自带的排序；
池子里的顺序还要交给精排模型重新学（见第五、六节——朴素按融合分排的 Top10 甚至不如直接推最热）。

## 三、实验 A：热门基线 vs ItemCF（含"是否换皮"检验）

同一批 2,843 个测试用户、同一测试篮。ItemCF 用"用户训练期已购集合的聚合余弦"打分（与特征里的 cf_agg_sim 同口径）。

| 方法 | precision@5 | precision@10 | recall@5 | recall@10 | hit@10 |
|---|---|---|---|---|---|
| 全局热门（基线） | 0.0254 | 0.0245 | 0.0076 | 0.0141 | 0.1868 |
| **ItemCF（画像余弦）** | **0.0526** | **0.0463** | **0.0160** | **0.0270** | **0.2775** |

换皮检验（列表级重叠，两个 Top-10 的 Jaccard）：**中位 0.177 / 均值 0.174** ——
ItemCF 与热门 Top-10 平均只有不到 1/5 重合，**不是"热门榜换皮"**，而是按用户画像给出了另一套更个性化的排序；
从 hit@10 看 ItemCF ≈ 热门 × 1.49，pre@10 ≈ ×1.9。

两个案例用户并排（✔=命中该用户下一单；完整存档 `experiment_a.txt`）：

- **用户 12682**（测试篮 30 种，两路都命中）：热门 Top10 只命中 `22138`（9 件套烘焙套装）1 个，
  ItemCF Top10 也只命中 `21931` 1 个——但两套列表**仅 3 个重合**（Jaccard≈0.18），
  各自命中的都是画像/热门里更"对口"的那个，明显不是同一份榜单。
- **用户 13048**（测试篮 30 种午餐袋/便当袋，两路都未命中）：热门 Top10 全是蛋糕架/烛台/彩旗等"大众热门"，
  ItemCF Top10 是另一批午餐袋/收纳袋（23209/23203/85099F…）——ItemCF 更贴近该用户"袋类采购"的画像，
  只是这批袋类恰好不在下一单；**两路都没押中，正好说明列表不是简单换皮**。

## 五、精排：LR 与 LightGBM（对应阶段五）

候选样本 = `recall_set.csv` 全量行（142,150），标签 = 是否落在该用户测试篮；
正样本 1,952（1.37%，下一单命中稀有，属正常长尾）。**用户级**切分 fit 1,990 / valid 853（seed=42），
同一用户候选不跨集合。10 维特征见下（顺序 = `rank_meta.json.features`）。

### 5.1 判别能力（valid AUC，越高越好）

| 模型 | valid AUC |
|---|---|
| LR（L2，class_weight=balanced，特征标准化） | **0.7664** |
| LightGBM（300 棵树，同特征同候选） | **0.7571** |

两者都明显 > 0.5，说明特征对"下一单命中"有真实区分力；LR 略高、差距很小（线性模型在这个低样本率任务上并不吃亏）。

### 5.2 LR 系数表（标准化后权重，绝对值可比）与解读

| 特征 | 含义 | 系数 |
|---|---|---|
| pop_buyers_log | 候选商品热门度（买家数 log） | **+2.452** |
| fl_pop | 是否来自热门路 | −0.583 |
| emb_sim_uservec | 与用户历史商品向量的余弦 | **+0.460** |
| user_n_owned_log | 用户历史去重品类数（log） | +0.403 |
| fl_sim | 是否来自相似扩展路 | +0.340 |
| pop_rank_frac | 热门排名（0=最热） | +0.320 |
| fl_vec | 是否来自用户向量路 | +0.149 |
| n_routes | 被几路命中 | −0.089 |
| price_log | 单价（log） | −0.066 |
| cf_agg_sim | 与用户已购画像的聚合余弦 | −0.028 |

直觉解读：

- **最热的品最可能被下一单买**（pop_buyers_log 权重最高）——批发补货特征明显；
  但"由热门路硬塞进来的溢出候选"（fl_pop）在同一热门度下反被压低：模型更喜欢"用户个性化路由召回的热门"。
- **与用户历史语义越近越加分**（emb_sim_uservec +0.46、fl_sim +0.34），用户向量路由的纯"口味迁移"候选权重最低（+0.15）。
- `cf_agg_sim` 在 LR 里几乎为 0 是**共线性**所致：它和热门度高度相关（越常被同批人买 → 越热门），
  LR 把信号全记到 pop_buyers_log 头上——但 LightGBM 给它的 gain 排第 2，非线性模型能"两条腿走路"（见 5.3）。

### 5.3 LightGBM 特征重要性（split-gain，Top6）

| 特征 | gain |
|---|---|
| pop_rank_frac | 876,993 |
| cf_agg_sim | 253,907 |
| emb_sim_uservec | 178,696 |
| pop_buyers_log | 152,131 |
| user_n_owned_log | 145,360 |
| price_log | 105,230 |

两种模型"看到的信号一致"（热门 + 用户语义 + 画像），只是线性模型因共线把画像权重转给了热门、树模型能同时用上。

### 5.4 正/负样本特征均值对照（哪个特征最分得开）

| 特征 | 正样本均值（命中） | 负样本均值（未命中） | 方向 |
|---|---|---|---|
| pop_buyers_log | 5.03 | 3.74 | 正样本显著更热门 |
| cf_agg_sim | 8.97 | 5.75 | 正样本与用户已购画像更像 |
| emb_sim_uservec | 0.279 | 0.300 | 微反向：用户向量"口味迁移"候选在预测下一单上反而是负号 |
| fl_vec（来自用户向量路） | 0.176 | 0.403 | 用户向量路候选命中率明显偏低 |

> 与实验 A 一致：在"预测下一单"上，**热门度 + ItemCF 画像比嵌入"同主题迁移"更有效**；
> 嵌入相似更适合做召回供给/搭配，而不是直接当排序分。

### 5.5 LR vs LightGBM 的 Top10 一致性

每 valid 用户各自取 Top10，两模型列表的 Jaccard **中位 0.429 / 均值 0.411**（中等重叠）：
多数用户两个模型的前排高度重合，差异集中在边界候选，因此线上两模型切换对体验影响有限。

## 六、汇总指标表（对应阶段六）与成败案例

同一批 **valid 用户 853 人**、同一候选池、同一测试篮；四行直接可比（存档 `metrics_summary.json`）：

| 方法 | precision@5 | precision@10 | recall@10 | hit@10 |
|---|---|---|---|---|
| 全局热门 Top10 | 0.0244 | 0.0265 | 0.0138 | 0.2028 |
| 融合召回 Top10（未精排） | 0.0190 | 0.0175 | 0.0129 | 0.1465 |
| **召回(50) + LR 精排 Top10** | **0.0408** | **0.0354** | **0.0227** | **0.2521** |
| **召回(50) + LightGBM 精排 Top10** | **0.0427** | **0.0372** | **0.0250** | **0.2626** |

怎么读这张表（重要结论，建议写进报告）：

1. **朴素"融合召回 Top10"是最弱的一行**（hit@10 0.1465 < 热门 0.2028）：召回只保证"候选装得进答案"，
   它自带的排序（名次归一化混合）不擅长预测下一单，甚至会因为塞入太多"口味迁移"候选而跑输热门。
2. **精排把 hit@10 从热门 0.203 / 召回 0.147 拉到 LR 0.252 / LGB 0.263**（相对热门约 +24%~30%），
   precision@10 约为热门的 1.4~1.5 倍，recall@10 约为 1.6~1.8 倍。
3. LR 与 LGB 很接近，LGB 在每项都略高一丝（AUC 略低 0.01，TopN 略高）——两者都远好于"热门/召回直接当结果"。

### 成功案例（用户 16855，测试篮 10 种）

LR Top10 **命中第 1、2、3、4、8 位（共 5/10）**，其中 Top1~4 正是用户下一单的整套 Regency 茶具：

| 排名 | 商品 | P(y=1) | 是否命中 |
|---|---|---|---|
| 1 | 23173 摄政风格玫瑰茶壶 | 0.869 | ✔ |
| 2 | 23175 摄政风格粉色牛奶壶 | 0.865 | ✔ |
| 3 | 23174 摄政风格绿色糖碗 | 0.860 | ✔ |
| 4 | 22423 摄政风格三层蛋糕架 | 0.765 | ✔ |
| 5 | 23163 摄政风格糖夹 | 0.717 | — |
| … | 23162 茶滤 / 23164 蛋糕铲 | … | — |
| 8 | 85123A 白色心形茶烛台 | 0.642 | ✔ |

解读：用户历史常买 Regency 粉色茶具，模型把"同单成套"的茶壶/奶壶/糖碗/蛋糕架排到最前，恰好补齐下一单——**精排把召回池里的同主题候选按用户口味顶到前列**。

### 失败案例（用户 15687，测试篮 12 种）

LR Top1 `22423 蛋糕架`（P=0.814）**未命中**，第 7 位 `22457 天然石板心形黑板` 才是本单真正会买的（本单另有 20970/22577/84347 等大量"家居黑板/架子"转向）。前几名全是该用户历史上最常买的热门类（蛋糕架/彩旗/午餐袋），模型被历史热门带偏，**没察觉这一单换成了"黑板/收纳"主题**——本质是"历史画像强、单次主题漂移"的冷启动难题，也解释了为何 hit@10 只能到 ~0.26 而非更高。

### 局限（如实写）

- 每用户只有"最后一单"一条标签，正样本仅 1.37%，指标对单用户噪声敏感；
- 候选池来自三路召回，模型**无法推荐池外商品**，召回漏掉 = 精排永远找不到（覆盖率的另一面）；
- LR/LGB 只差 0.01~0.01，本数据不足以断言谁更优，只能说不论哪个都显著优于热门基线。

## 七、Flask 在线演示与截图

运行：`venv\Scripts\python.exe web\app.py` → 默认 `http://127.0.0.1:5001`（可用 `PORT` 换端口）。
演示 ID：用户 `12597`（LR 演示）`13899`（LGB 演示），商品 `85123A`、`22423`。

| 端点 | 说明 |
|---|---|
| `/` | 演示主页（演示 ID + 接口入口） |
| `/similar?item_id=85123A&topn=5` | 商品相似（默认 Item2Vec，可加 `method=itemcf` 换口径） |
| `/recommend?user_id=12597&topn=10&ranker=lr` | 召回50 → LR 精排 Top10 |
| `/recommend?user_id=13899&topn=10&ranker=lgb` | 召回50 → LightGBM 精排 Top10 |
| `/baseline?user_id=12597&topn=10` | 热门 / ItemCF / 融合召回 三路基线对照 |

任一接口加 `&format=json` 直接联调。在线推荐全链路：`/recommend` 取用户全量历史 ctx →
三路融合召回 50 → 提 10 维特征 → 加载 `lr_model.pkl / lgb_model.pkl` → 概率排序取 TopN，
与离线脚本共用 `src/recommender`（`recall_fusion / features_for_rows / score_rank`），"在线排序函数"即该共用实现。

# 候选集打分线 · 版本命名规则说明

> 用途：一页看懂 `cand-align-v13-v15blend65` 这类名字**怎么拆、每段谁定的**，以及本线
> **全部版本号的含义与出处**。
> 数据来源：`提交版本记录.md`（榜分权威）。
> 生成日期：2026-09-10。

---

## 1. 总公式

```
cand-align  -  v13  -  v15  blend65
   │           │      │      │
 交付线名   我方版本号 组长版本号  融合权重
```

`<交付线名>-<我方版本号>[-<对方版本号><操作><参数>]`

| 段 | 含义 |
| --- | --- |
| `cand-align` | **交付线名**（「候选集对齐回放链」），2026-09-08 起的新线，用来区别于旧答辩链；这条线的每个提交都带这个前缀 |
| `v13` | **我方**在这条线的第 13 个提交配置。命名规则是 `vN = 第 N 个提交配置`（**不是"第 N 次重训才递增"**），见 `提交版本记录.md:54` |
| `v15` | **组长黄俊霖**的模型版本号（`traincsv-v15-activity-moe`），**不是我们的编号** |
| `blend65` | 秩融合 + 权重：`0.65×rank(组长 v15) + 0.35×rank(我方 v6)` |

> ⚠️ **最容易误读的一点**：`v13` 和 `v15` 来自**两套互不相干的编号体系**，只是恰好挨着。
> 它**不是**"我方 v13 模型 融 我方 v15 模型"，而是"**我方第 13 版 = 拿组长 v15 做跨架构融合**"。

## 2. 全文件命名约定

同一个版本号会出现在三类产物里，文件名互相可推导：

| 产物 | 命名模式 | 例 |
| --- | --- | --- |
| 提交文件 | `outputs/candidate/sample_submission_<版本号>.csv` | `sample_submission_cand-align-v13-v15blend65.csv` |
| 配方 meta | `models/candidate_meta_<版本号>.json`（记权重/特征序/cut） | `candidate_meta_cand-align-v6-fuse.json` |
| 分量模型 | `models/candidate_<版本号>_{lgb,xgb,lr}.pkl` | `candidate_cand-align-v6-fuse_lr.pkl` |

脚本约定：`scripts/<NN>_<动词>.py`，编号即大致执行顺序；`NN` 只保证唯一、不代表依赖。

## 3. 四类前缀（交付线 / 目的）

| 前缀 | 含义 | 覆盖范围 |
| --- | --- | --- |
| `cand-lgb-*` | **旧链**：候选集打分最早的 LightGBM 单模型链（33 特征） | `cand-lgb-v1 / v2 / v3` |
| `cand-probe-*` | **探针**：反推老师评分口径用，**不计入正式提分**（分低不影响榜最佳） | `cand-probe-rank`、`cand-probe-block` |
| `cand-fm-*` | **FM 模型**：numpy FM（老师点名的模型族） | `cand-fm-v1`（= 记录里的 v4） |
| `cand-align-*` | **主线**：候选对齐回放链（对标组长 v9 方法），v6 / blend65 都在这里 | v1 … v15pu |

## 4. 后缀词表（一看到就知道它改了什么）

| 后缀 | 全称 / 含义 | 改动内容 |
| --- | --- | --- |
| `-macro` / `-macrosp` | 用户加权 macro / macro × scale_pos | 训练行权重的两种口径 |
| `-fuse` | 多分量**秩融合** | 两个及以上模型按全局百分位秩加权 |
| `-pooled` | 融合权按**池化 AUC** 选 | 换选权口径（只看全局池化序） |
| `-tune` | **调参**冠军配方 | 组等权细网格调参选出的超参组合 |
| `-ext` | **前伸**训练池 | 训练池从 5 个月扩到 9 个月（Feb..Oct） |
| `-h2` / `-h1sep` | 视界 **H≥2** / **H1 对照** | 标签窗改「本月∪下月买」/ 只丢最近月做归因 |
| `-season` | **季节性** 12 月赌注 | serve 侧对圣诞货加 δ |
| `-lr75` | **LR 权 .75** | 融合权外推（LR 侧重 .6→.75） |
| `-als25` / `-als35` | **ALS 分量占比** .25/.35 | 加矩阵分解作第 4 分量 |
| `-v15port` | **移植** 组长 v15 | 把对方三机制装进我方引擎 |
| `-v15blendNN` | 与组长 **v15 跨架构秩融合**，`w_v15=NN` | NN = 65 表示 0.65×组长 + 0.35×我方 |
| `-v15pu-blendNN` | 同融合，但 **per-user（组内）百分位** | 归一化改 `rank_within_user` |
| （无后缀） | **单模型**基线 | 无融合 |

## 5. 我方版本号是怎么排的（v1 → v15）

```
v1 → v2-macro / v2-macrosp → v3-fuse → v4-fuse → v5-fuse → v6-fuse（纯 own 冠军 0.7782）
   → v7-pooled / v7-tune → v8-ext → v9-als25/35（ALS 赌注被门禁拦，未上板但占了号）
   → v10-h2 / v10-h1sep → v11-season → v12-lr75 → ★v13-v15blend（跨架构融合）
   → v14-v15port / v14b（移植线，不烧板）→ v15pu（归一化轴，失败）
```

到 **v13** 这一版，引入的新东西就是"**跨架构秩融合**" ⇒ v13 = 融合线的槽位。
`v9` 因为 ALS 赌注占了号（虽未上板），所以序号不留空。

**同一族的兄弟**：`v13-v15blend60/65/70/75/85/92/97/99` = 完全相同的融合、**只改权重 w**
（65 是峰值 0.7863）；`v15pu-blend65/70` 里的 **`pu` = per-user**（组内百分位归一化），
是另一条**已证伪**的轴（0.7852 < 全局 0.7863）。

## 8. 三条记忆口诀

1. **前缀看"哪条线"**：`cand-lgb`=旧链、`cand-probe`=探针、`cand-fm`=FM、`cand-align`=主线。
2. **vN 看"第几个配置"**：只表示提交顺序槽位，**不代表重训次数**，也不跨线通用。
3. **`v13-v15` 是两个体系的号**：前一个是我方的，后一个是组长的——**相邻纯属巧合**。

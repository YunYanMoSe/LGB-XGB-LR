# 阶段四 · 5 路召回融合报告

> 任务：在已有清洗数据与 Item2Vec 商品向量的基础上，实现 5 路候选召回并把每路按配额融合成 50 条候选，覆盖「热门 / 相似扩展 / 用户向量 / 协同过滤 / 最近会话」五类信号；同时产出一份用户商品向量，并做配额对照实验。
> 对应代码：`scripts/04_build_recall.py`；配额配置在 `config/settings.py` 的 `HYPERPARAMS["recall5"]`，随机种子固定 **seed=42**。

## 一、任务目标

把「候选召回（Recall）」从单一信号升级为 5 路融合：

- 每路都完成 `user_id → 商品列表` 的映射，且**过滤掉该用户已购商品**（避免重复推荐已买过的东西）；
- 各路候选按**配额**（quota）融合：按固定路序逐路取数、跳过重复 ID、凑满 50 条即停，保证"多路供给、总量可控"；
- 无购买历史的**冷启动用户**直接返回热门路，并置 `is_cold_start=True`；
- 最终把每用户的召回列表写成长表 CSV，便于后续阶段读取复用。

## 二、输入数据

| 输入 | 说明 | 来源 |
| ---- | ---- | ---- |
| `data/processed/clean_transactions.csv` | 清洗后交易：397,884 行 / 4,338 用户 / 商品库 3,665 种 / 18,532 笔订单 | `scripts/01` |
| `models/item2vec.model` | Item2Vec（Skip-gram）商品向量模型，词表 3,177 | `scripts/10` |

> 说明：本阶段使用用户**全部历史**（含最近一单）计算各类信号，面向"候选生成层"的覆盖能力评估，与 `scripts/11` 的"每用户最后一单留出"协议口径不同，两套 `recall_set` 数字不可直接对比。

## 三、五路召回设计

每路生成候选时，若同一商品从多个种子/邻居出现，保留**最高相似分**并去重，再按分数降序、过滤已购、截断到 50 条。五路及配额如下（配额总和 = 50）：

| 路 | 候选逻辑 | 配额 |
| ---- | ---- | ---- |
| ① 热门 `popular` | 全库销量（Quantity 求和）降序，剔除该用户已购后取前 N | 10 |
| ② 相似扩展 `similar` | 用户**每件**历史购买商品取 Item2Vec 相似 Top-5，合并邻居 | 10 |
| ③ 用户向量 `user_vec` | 历史商品向量取平均并单位化 → 与全词表做余弦近邻 | 15 |
| ④ ItemCF `itemcf` | 阶段三同口径的「商品 × 用户」矩阵现算余弦相似，历史商品相似品 Top-5 合并 | 10 |
| ⑤ 最近会话 `recent` | 取用户**最近一张发票**内商品，做 Item2Vec Top-5 扩展合并 | 5 |

设计要点：

- **③ 用户向量**是模型的副产品：把每件商品 128 维向量按"用户历史购买"做平均，得到该用户的偏好向量，全量存成 `models/user_vectors.pkl`（4,338 用户 × 128 维，单位化 float32）。该向量既可当召回路，也可供后续精排阶段当用户侧特征。
- **④ ItemCF** 没有落盘相似矩阵，而是运行时复用 `src/item_similarity`（`load_item_matrix` + `top_k_similar_rows`，与 `scripts/05` 同一张「商品 × 用户」数量矩阵口径）现算邻居表，3,665 件商品约 1s 完成，保证口径与阶段三一致。
- **⑤ 最近会话**引入"时效"信号：用户在最近一笔订单里的商品最能反映当前购买意图，仅给 5 个配额，起补充作用。
- **冷启动**：离线数据集里所有 4,338 个用户都有购买史，故统计恒为 0；该分支主要为**在线新用户**保留——无历史时走热门路直接返回 50 条并标记。

## 四、融合规则

1. 初始化 `seen` = 该用户已购集合（融合过程天然不会再放进已购）；
2. 按路序 `popular → similar → user_vec → itemcf → recent` 逐路处理；
3. 每路从自己的候选列表里，跳过已在 `seen` 的商品，最多补充至**该路配额**；
4. 候选总数达到 **50** 立即停止；若五路耗尽仍不足 50，则保留实际条数（不硬凑）。

路口径小结（写进程序注释与本文，答辩口径统一）：

- 覆盖率 = `(各用户召回表并集 ∩ 商品库) / 商品库`，衡量融合召回对商品库的覆盖面；
- 热门占比 = `召回条目中命中「全局销量 Top-100」的条数 / 召回总条目`，衡量结果中大众商品的浓度（个性化路占比高 ⇒ 长尾覆盖好）；
- 平均 `list_length`、满 50 用户占比 = 融合配额的实际填满程度。

## 五、运行与实现

```bash
venv\Scripts\python.exe scripts\04_build_recall.py
```

- 一次性构建 5 路候选后，在**同一批候选池**上分别按默认配额与对照配额融合，两组指标同时落盘，单次运行约 16s；
- 输出物（幂等，可重复运行）：

| 产物 | 内容 |
| ---- | ---- |
| `data/processed/recall_set_5route.csv` | 长表：`user_id, recall_list（逗号分隔商品码）, list_length`，共 4,338 行 |

| `outputs/stage04_coverage.txt` | 覆盖率 + 热门占比 + 平均列表长 + 满 50 占比 + 示例 |

> 与已有 `data/processed/recall_set.csv`（`scripts/11` 三路召回，供 `12`/web 使用）**并存互不影响**，本阶段结果单独存为 `recall_set_5route.csv`。

## 六、实验指标与结果

默认配额（10/10/15/10/5，seed=42，N=4,338 用户，商品库 3,665）：

| 指标 | 数值 |
| ---- | ---- |
| 召回总条目（Σ list_length） | 213,762 |
| 去重召回商品数 | 3,137 |
| 覆盖率（去重召回 / 商品库） | **85.59%** |
| 热门占比（命中全局 Top-100） | 22.08% |
| 平均 list_length | 49.3 |
| 满 50 用户占比 | 88.7% |
| 冷启动用户数 | 0（离线全员有购买，恒 0） |

数据校验（脚本输出后逐行复核）：4,338 行全部字段齐整；**任一行内零重复、零已购残留**；列表长度 15–50。

结果读法：

- **覆盖率 85.59%**：5 路融合把 3,665 种商品里的 3,137 种都送进了某位用户的候选表，商品库覆盖面广；
- **热门占比仅 22.08%**：即约 78% 的召回条目来自全局 Top-100 之外——`similar / user_vec / itemcf / recent` 四条个性化路提供了大量长尾商品，说明向量与协同过滤确实在"扩充候选多样性"上起作用，而不是简单复读热门榜；
- 平均 49.3、88.7% 用户填满 50 条：配额融合基本能把候选打满；个别历史极丰富的用户（买过很多种商品）剩余可推荐空间天然偏小，列表不足 50 属合理。

示例（历史最丰富用户 14911，Top-10）：`23843, 22616, 17003, 84568, 22998, 21931, 21137, 22659, 84212, 21326`。

## 七、配额对照实验

控制变量：候选池与用户完全相同，仅把热门配额从 10 提到 20（从 `user_vec` 借走 10，总量仍 50）：

| 口径 | 覆盖率 | 热门占比 | 平均 list_length | 满 50 占比 |
| ---- | ---- | ---- | ---- | ---- |
| 默认配额 10/10/15/10/5 | 85.6% | 22.1% | 49.3 | 88.7% |
| 调大热门 20/10/5/10/5 | 83.4% | 41.8% | 49.3 | 89.4% |

结论：热门配额翻倍让热门占比从 22.1% 升到 41.8%，但商品覆盖率从 85.6% 掉到 83.4%——热门商品的重复率更高，挤占了向量路的长尾名额。默认配额在"大众热销"与"个性化长尾"之间更均衡，故取 10/10/15/10/5 为正式配置。

## 八、小结与展望

- 5 路召回把**销量热度、向量语义、协同过滤、购买时效**四类互补信号统一到同一张候选表，覆盖率 85.59%，且多数条目来自个性化路（长尾），符合"候选生成要广"的定位；
- 冷启动在离线统计中不出现，但代码保留热门路回退 + `is_cold_start=True` 标记，供在线场景直接使用；
- 配额对照实验支撑了默认配额的选取，也可作为答辩中"参数为什么这么定"的依据；
- 后续：可将 `recall_set_5route.csv` 喂给精排（LR/LightGBM）与 `scripts/11/12` 同协议对比 Hit@10，量化"5 路 vs 3 路"对最终排序收益的贡献。
